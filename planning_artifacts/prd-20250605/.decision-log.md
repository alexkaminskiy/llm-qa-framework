# Decision Log: LLM QA Framework PRD

## Session 2026-06-05 — Discovery & Draft

### Decision 1: Judge LLM Selection
**Date:** 2026-06-05  
**Decision:** Use Groq `llama-3.3-70b-versatile` as the evaluation judge.  
**Rationale:**
- Free tier suitable for research/learning scope.
- Fast inference (acceptable latency for offline evaluation).
- Reasonable quality for faithfulness/relevance assessment.

**Alternatives Considered:**
- OpenAI GPT-4: Higher cost, not justified for learning project.
- Local open models: Slower, less stable for evaluation.
- Claude: Cost, latency similar to GPT-4.

**Status:** ✅ Accepted (PRD section 1 & Technical Stack)

---

### Decision 2: Baseline Tracking Approach
**Date:** 2026-06-05  
**Decision:** Commit `baseline.json` after each known-good eval run; compare subsequent runs against it with configurable drift thresholds.  
**Rationale:**
- Simple, auditable, version-control-friendly.
- Enables regression detection without external services.
- Allows per-metric thresholds (e.g., faithfulness tolerance ≠ relevance tolerance).

**Alternatives Considered:**
- Database-backed baseline tracking: Over-engineered for research scope.
- Embedded thresholds in code: Harder to adjust, less visible.
- Time-series tracking: Deferred (out of scope for v1).

**Status:** ✅ Accepted (PRD section 3)

---

### Decision 3: Scope Boundary: Offline vs. Online Monitoring
**Date:** 2026-06-05  
**Decision:** This framework is **offline evaluation only**. Real-time production monitoring (latency, error rates, live drift) is explicitly out of scope.  
**Rationale:**
- Offline is sufficient for research/learning goal.
- Online monitoring requires distributed tracing, observability stack (not part of test framework).
- Cleaner boundary; reduces scope creep.

**Status:** ✅ Accepted (PRD "Out of Scope")

---

### Decision 4: Traceability Mechanism
**Date:** 2026-06-05  
**Decision:** Use pytest markers (`@pytest.mark.requirement("SYS-REQ-NNN")`) + script-driven TRR generation.  
**Rationale:**
- Lightweight, no external database.
- Pytest-native, familiar to engineers.
- Script can regenerate TRR without re-running LLM tests (cost-efficient).

**Alternatives Considered:**
- Custom annotation system: Reinvents the wheel.
- External test management tool: Overkill for research project.
- Manual traceability matrix: Not scalable, error-prone.

**Status:** ✅ Accepted (PRD section 6 & Technical Stack)
